# Preview security model

SvgLiveEditor treats source files as hostile input and uses several independent controls before pixels reach the preview.

## Validation boundary

`SvgValidationService` parses with .NET `XmlReader` using `DtdProcessing.Prohibit`, a null `XmlResolver`, and a ten-million-character document limit. It requires an SVG root in `http://www.w3.org/2000/svg` and rejects:

- DTD/entity declarations and XML processing instructions;
- elements outside the SVG namespace;
- `script`, `foreignObject`, hyperlinks, and active embedded web/media elements;
- inline event-handler attributes and `xml:base`;
- `<style>` elements and CSS imports;
- non-fragment `href`/`src` values and non-fragment CSS `url(...)` values.

These rules are conservative. Unsupported content produces a visible validation error and does not replace the last valid preview.

## Inbound file boundary

Open and window-wide drag/drop share the same strict UTF-8 reader and document-loading pipeline. File reads are bounded to 10,000,000 bytes before decoding, while XML parsing retains its independent ten-million-character bound. The drop adapter reads only the Windows `FileDrop` format and accepts exactly one fully qualified local `.svg` or `.txt` regular file. It rejects empty or multiple payloads, directories, `.lnk` shortcuts, reparse points, UNC/URL paths, unsupported extensions, missing files, unreadable metadata, and oversized files. Unicode text, HTML, browser URL, virtual-file, and arbitrary string payloads are never interpreted as paths.

The drop overlay is informational and non-hit-testable. A supported drop still runs the existing unsaved-change decision before reading or replacing the current document. Cancel leaves the document source, path, modified state, Inspector, and preview unchanged. A successfully read file is loaded as exact editable text even when its XML is invalid; normal validation then reports line/column information and the last valid safe preview remains visible.

## Document inspector boundary

The element tree is built only after `SvgValidationService` accepts the current source. The index stores source offsets and hierarchy; it does not expose a browser DOM and does not add IDs or metadata. Supported property changes replace one existing attribute value or insert one missing attribute in the selected start tag, then pass through the same validator and preview pipeline. The application never serializes the full XML document for an inspector edit, so unrelated whitespace, comments, attribute order, and UTF-8 text remain untouched.

## Layers and groups boundary

Layers is a WPF-only, topmost-first projection of the same validated source index. It includes eligible artwork and existing `<g>` containers while definition-only content remains in Structure. Random opaque row identities exist only in process memory and are reconciled conservatively across current valid revisions; they are never written into SVG or sent to WebView2. Layer selection uses the existing host selection path, so duplicate authored IDs do not become trusted identifiers.

Creation accepts only the fixed app-owned `rect`, `circle`, `ellipse`, `line`, direct `text`, and empty `g` kinds. Defaults are finite and bounded from the validated canvas or `viewBox`; no raw element name, markup, attribute, or ID is accepted from the UI. New content is inserted at a source-style-aware exact location and the complete candidate is validated before one AvalonEdit Undo group is applied. Duplicate copies one exact current subtree next to the original, assigns deterministic globally unique IDs, and rewrites only analyzed local `href` and `url(#id)` references in the copy. Missing, duplicate, ambiguous, or excessively complex reference targets fail closed. Delete removes one exact current subtree and rejects a selection that has known external local references; deleting a meaningful non-empty group also requires explicit confirmation.

Arrange moves only exact current full-element spans among eligible siblings under one exact indexed parent and never infers a parent change. Layers drag/drop uses explicit before, after, or inside-group placement. A cross-parent reparent operation rechecks the current source revision and text, opaque row identity, element and target spans, ancestry/cycles, definition boundaries, inherited session locks, and semantic context before applying one minimal validated edit. Moving between contexts with transforms, styles, presentation/inheritance attributes, opacity, clipping, masks, filters, typography, visibility, namespace declarations, or other ambiguous semantics fails closed rather than changing appearance. The internal WPF drag payload contains only one current opaque row identity and remains separate from the window-wide untrusted FileDrop path. Stale rows, self/descendant drops, definition targets, locked layers, invalid candidates, and no-op boundaries fail closed.

The eye control does not maintain a second rendering model. For an element with no authored `display`, `visibility`, inline style, or matching animation ownership, it can add a direct standard `display="none"`. It can remove that attribute only while the current document session records it as app-owned. Existing authored visibility semantics are disabled with an explanation rather than overwritten. Hidden descendants reflect effective parent state. The candidate is span-checked and validated, and each accepted toggle is one source Undo operation.

SVG has no portable editor-lock attribute, so locks are deliberately session-only and never serialized. A parent group lock is inherited by its visual descendants and guards host-side Create into that parent, Duplicate, Delete, Move, Resize, Nudge, Arrange, Layers reorder/reparent, Opacity, and supported Properties mutations. It removes resize handles but does not prevent selection or direct Source editing. Locks are an accidental-edit UX guard, not a security boundary.

## Visual editing boundary

Visual selection does not turn the untrusted SVG into an interactive browser DOM. After normal validation, .NET derives a bounded host-side geometry index for untransformed `rect`, `circle`, `ellipse`, and `line` elements whose required geometry is unitless or uses `px`. Those four shape types can also expose bounded host-owned resize handles; direct simple `<text>` remains movable but is resized only through its validated `font-size` property. Percentage/list/unsupported units, nested `tspan`/`textPath`/animation, layout offsets, transforms, stroke, complex typography, and clipped, masked, or filtered content are not approximated, moved, or resized. Pointer coordinates are mapped through the current image rectangle, intrinsic canvas, `viewBox`, `preserveAspectRatio`, zoom, scroll position, and display scale before host-side topmost hit testing or resize calculation.

Unsupported direct `path`, `polygon`, and `polyline` artwork is never made movable. Simple unitless path/point syntax with reliable conservative host-side bounds may be selected for inspection through the same host-owned rectangle overlay; it cannot start a move or nudge. Those bounds also prevent selection from clicking through a topmost unsupported element. Curved, transformed, marker-decorated, effected, malformed, or otherwise unreliable artwork remains an unlocalized fail-closed blocker with a bounded status reason. Definition-only children under `defs`, gradients, markers, masks, patterns, symbols, and clip paths are not indexed as independently visible artwork.

Text bounds are produced by Chromium's SVG shaping engine in the fixed trusted page, not by estimating glyph widths in .NET. The host sends only bounded decoded direct text plus constrained `font-family`, size, weight, style, anchor, direction, and bidi fields. The request is exact-schema, navigation-token-bound, source-revision-bound, random-request-ID-bound, count-limited, and coordinate-limited. The script creates a temporary app-owned off-screen SVG `<text>` node, assigns plain text only through `textContent`, applies only those allowlisted fields, reads `getBBox()`, and removes the node and surface. It never receives markup, uses `innerHTML`, or accesses the isolated SVG image DOM. The host accepts only one matching exact result set with finite bounded rectangles. Failed or unreliable metrics leave that text unavailable to Preview movement while Source and Inspector remain usable.

The visible selection outline and fixed-screen-size resize handles are separate app-owned overlays in the trusted HTML shell. They are built only from host-generated element kinds, known handle identifiers, opaque random selection identities, and finite bounded numeric geometry; raw source, attribute text, element markup, and SVG identifiers are never inserted into them. Page-to-host visual pointer, resize, and nudge messages have exact command-specific schemas and must match the current unpredictable navigation token and validated source revision. Resize messages must additionally match the current selection identity, one known handle, a fresh random gesture identifier, and the current physical primary-button state. The host rejects stale or replayed gestures, stale revisions, stale spans, mismatched elements or handles, non-finite or out-of-range coordinates, modifier mismatches, invalid source, pending validation, navigation races, and unsupported geometry.

A visual move or resize drag updates only the app-owned outline and handles until pointer release. The validated source remains unchanged during pointer movement. On release, the host creates one minimal start-tag edit for only the required position or size attributes and applies it to the AvalonEdit document as one Undo operation. Crossing an anchored resize edge clamps at 0.01 SVG user units rather than flipping geometry. Escape, pointer cancellation or capture loss, focus/window loss, navigation, source revision changes, and invalid source cancel without an edit. Arrow-key nudges use the same guarded movement path and are routed only while Live Preview has actual keyboard focus. Every committed edit re-enters normal validation, Inspector indexing, preview, Recovery, and validation-gated Auto Save; unrelated whitespace, attribute ordering, line endings, and Persian UTF-8 text are not reserialized.

## Local persistence boundary

Crash-recovery source is written only beneath the current user's fixed `%LocalAppData%\SvgLiveEditor\Recovery` directory. Snapshot names use 128-bit random application-generated identifiers and are never derived from a document path, display name, or source. Writes use create-new temporary files and atomic same-directory replacement. The loader accepts only the current exact JSON schema and validates identifier syntax, identifier/filename agreement, metadata, normalized supported original paths, the 10,000,000-byte UTF-8 source limit, and an exact SHA-256 of the source. Recovery files and their immediate parent directory must not be reparse points. Malformed, oversized, expired, tampered, or mismatched records are rejected and removed. Retention is bounded to seven days, ten snapshots, and 100,000,000 bytes.

The stored original path is metadata, not a source location. Recovery always restores the exact source contained in the validated snapshot. A path is retained only as an in-memory document association when the existing local SVG/TXT file passes the safe read policy; otherwise the snapshot opens as recovered untitled work. A byte-identical snapshot is removed without prompting. Restore never writes the original, Discard deletes only the selected managed snapshot, and Skip retains it for a later launch.

Auto Save is a separate opt-in pipeline and is disabled by default. It applies only to an existing named `.svg` or `.txt` document that was manually opened or saved, including a safely reopened last document. The exact captured revision must pass `SvgValidationService`; invalid XML pauses automatic writes while recovery continues. Network paths, missing files, directories, read-only files, unsupported drives, inaccessible paths, file or directory reparse points, and policy failures are rejected. Exact UTF-8 bytes are staged to a random create-new temporary file in the target directory. Immediately before atomic replacement, the host rechecks the target policy and confirms that the document session, revision, path, and full source still match. A stale delayed write is disposed and cannot overwrite a newer edit. Manual Save and Save As retain their existing behavior.

## Rendering boundary

Validated source is encoded as UTF-8 and then Base64. A trusted, fixed HTML host loads it through an `<img src="data:image/svg+xml;base64,...">`; raw source is never concatenated into markup or an iframe `srcdoc`. Image-mode SVG does not provide an interactive document scripting surface.

The host Content Security Policy defaults all sources to none and permits only the Base64 data image, fixed inline host CSS, and one fixed app-owned interaction script authorized by its exact SHA-256 hash. The same LF-normalized script bytes are used both for hashing and insertion. The script handles preview wheel scrolling, pointer panning, bounded visual pointer/nudge requests, the app-owned selection overlay, focus-sensitive copy requests, fixed context-menu requests, bounded text measurement, and bounded full-image PNG rendering. It receives no SVG markup; the only source-derived value outside the isolated image is bounded host-validated plain text for measurement. It does not expose an SVG DOM, call `eval`, use `innerHTML`, load code, navigate, access files, or make network requests. Connections, remote fonts, media, objects, forms, and base URL changes remain disabled. Text rendering may use fonts already installed in Windows or the declared generic fallback; SvgLiveEditor never downloads, embeds, or packages third-party fonts.

Copy Preview, direct artwork drag, and Drag Image render only the already validated `<img>` into a transparent, app-owned off-screen canvas at dimensions selected by the host. They do not capture the viewport, checkerboard, scrollbars, window chrome, editor, or Inspector. The requested output preserves aspect ratio and is bounded to 4096 pixels per side and 8,000,000 pixels total. Oversized SVG canvases are scaled down before a browser canvas or host bitmap is allocated. Rendering does not navigate or modify source, preview zoom, or scroll state.

The host revalidates the returned PNG before clipboard or drag use. Direct artwork drag and Drag Image then write only those validated PNG bytes to a random create-new filename under `%LocalAppData%\SvgLiveEditor\DragOut` and publish Windows FileDrop, PNG, and Bitmap data formats. The filename is never derived from SVG source and the DataObject contains no SVG/XML. Cancelled drags are deleted when safe. Successful files are retained for asynchronous drop consumers and cleaned at startup, before creation, and every six hours. Managed files older than 24 hours are removed; the store is bounded to 20 files and 200,000,000 bytes. Cleanup errors are contained and cannot crash startup.

## WebView2 boundary

WebView2 enables scripting only so the CSP-hashed trusted host interaction script can run. The SVG remains a Base64 image rather than a DOM document, so SVG scripts cannot execute in the host context. Web messages use exact command-specific schemas and the unpredictable per-navigation token. The application rejects malformed messages, unknown commands, unexpected fields, stale tokens, unexpected sources, out-of-range values, and unsupported directions. `NavigateToString` gives the trusted page an opaque `about:blank` message origin, so source validation is paired with that token rather than trusting the origin alone.

SVG bidi presentation remains source-owned and passive. The Inspector exposes only constrained `direction`, `unicode-bidi`, and `text-anchor` values for text/tspan elements; directional override values are not offered. These edits use the same stale-span checks, single source edit, strict SVG revalidation, and one-operation Undo path as other properties. The preview does not infer language, rewrite text, add invisible bidi controls, or create hidden direction state.

Host-to-page messages can only update the existing image's zoom/normalized viewport, set Pan mode and the bounded Windows drag thresholds, set or clear one bounded app-owned visual-selection outline for the current source revision, request bounded text metrics for an exact host-approved set, or request a bounded PNG from the existing image. Page-to-host messages can only report normalized viewport state, request a bounded zoom/Pan command, report a token/revision-bound visual pointer gesture or one-axis nudge, return one exact matching text-metric set, request the fixed app-owned context menu at bounded viewport coordinates, request focus-sensitive copy, perform the paired direct-drag arm/start/cancel handshake, return a fixed PNG error, or return one matching PNG response. Direct PNG drag requires explicit `Alt`+primary drag on the isolated image; Select primary drag is reserved for supported element movement, while Pan mode, `Ctrl`+left, Space+left, and middle-button drag retain panning priority. The host independently validates the `about:blank` source, current navigation token, exact schema, current source revision, random request or gesture ID, bounded coordinates, system-distance threshold, current tool state, and physical button/modifier state. Focus loss, navigation, cancellation, pointer leave, or pointer termination resets active gestures. A PNG response must match the pending navigation token and random request ID and have the exact schema, `image/png` MIME type, requested dimensions, bounded Base64 and decoded lengths, PNG signature, valid chunk framing, one matching IHDR, image data, and a terminal IEND before it reaches the Windows clipboard decoder. Only one PNG request can be pending, and navigation cancels it. No arbitrary command dispatch or host object is available.

Script dialogs, host objects, permissions, downloads, pop-ups, external navigation, browser context menus, developer tools, pinch zoom, password saving, and autofill remain disabled. Right-click is canceled inside the trusted page and can open only the WPF-owned menu containing Copy Preview as PNG, Fit, and Reset Zoom; it cannot expose browser navigation, printing, page saving, inspection, or external-link commands. WebView2's Ctrl+Wheel dispatch is enabled because disabling its zoom controls suppresses the physical wheel event before the trusted page can receive it. The page captures Ctrl+Wheel with a non-passive listener, prevents native document zoom, and asks the host to resize only the SVG image; a host-side guard keeps the WebView zoom factor at 100%. Resource interception permits only the initial blank document, the generated `data:text/html` host, and the `data:image/svg+xml;base64` image, and returns a blocked response for everything else. No host object is exposed to SVG content.

The WPF preview uses `WebView2CompositionControl` so Windows drag input remains in the WPF visual/input tree rather than being captured by a separate browser child HWND. WebView2 external drop handling is disabled, so files are never navigated or opened by the trusted page. The composition control changes input routing only; it uses the same CoreWebView2 environment, CSP-hashed page, navigation policy, message validation, resource interception, and 1.0 document zoom guard.

The MVP uses the installed Evergreen WebView2 Runtime. A self-contained .NET publish does not bundle that runtime.

WebView2 profile and cache data is stored under the current user's local application-data directory, not beside the executable. The publish script builds in a clean staging directory and refuses to package an `EBWebView` or `*.WebView2` directory, preventing local browsing state or locked runtime files from entering the release archive.

## Residual risk

Complex graphics can consume CPU or memory even without active content. The XML character cap and PNG output caps limit source and bitmap size but are not complete rendering-complexity or rendering-time limits. PNG structural validation does not independently reimplement every decoder check; WPF's image decoder performs the final decode after the bridge-specific bounds and structure checks. Users should avoid opening deliberately adversarial files from unknown sources, and future releases should consider configurable file-size and rendering-time limits.
